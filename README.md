# Stellar XDR Conformance Kit

A shared, offline test kit for software that reads Stellar ledgers: indexers, ETL pipelines, wallet backends and SDKs.

This repository is the **prototype** behind [Walnut](https://www.walnut.dev)'s proposal for the Stellar Community Fund RFP ["XDR/CAP-Coverage Audit Tool and Indexer-Hardening Guide"](https://stellar.gitbook.io/scf-handbook/scf-awards/build-award/rfp-track#current-open-rfps). It holds what the RFP asks a proposal to include: a draft manifest schema, sample corpus entries, and evidence of reproducing listed bugs.

## What is here

- **A manifest schema** for corpus entries ([`schema/manifest.schema.json`](schema/manifest.schema.json), explained in [`docs/manifest-schema.md`](docs/manifest-schema.md)). One manifest per entry plus a generated, streamable [`corpus/index.jsonl`](corpus/index.jsonl).
- **Ten corpus entries** ([`corpus/entries/`](corpus/entries/)): raw XDR plus a manifest with provenance, CAP and protocol tags, and what a correct reader must produce. Four are whole ledgers (`LedgerCloseMeta`), six are single XDR values for SDK checks.
- **Reproductions** of public bugs from those entries ([`repro/`](repro/README.md)), with scripts, logs and limits.
- **The architecture** of the full kit (corpus, generator, replay harness, SDK conformance runner, linter, guide), with diagrams: [`docs/architecture.md`](docs/architecture.md).
- **A catalogue** of the 18 sightings the RFP lists, with XDR types, CAPs, root causes and fix commits ([`docs/bug-catalogue.md`](docs/bug-catalogue.md)).

## Results

Each bug was run at the pre-fix version and at the fix. All six bugs named in the RFP's reviewer checks are covered.

| Bug | Entry | Pre-fix | Fixed |
| --- | --- | --- | --- |
| [wallet-backend#729](https://github.com/stellar/wallet-backend/pull/729): ingestion halts on a signed-payload signer | `cap0040-signed-payload-signer-added` | mishandled (halt) | pass |
| [wallet-backend#731](https://github.com/stellar/wallet-backend/issues/731): SAC-created trustline has no state change | `cap0073-sac-trust-creates-trustline-signed-header` | dropped | pass |
| [wallet-backend#716](https://github.com/stellar/wallet-backend/issues/716): addresses silently truncated | `cap0040-signed-payload-signer-added`, `cap0027-muxed-source-on-soroban-ttl-op` | mishandled | pass |
| [js-stellar-sdk#1766](https://github.com/stellar/js-stellar-sdk/pull/1766): issuer and map-key ordering | `cap0038-pool-assets-issuer-byte-order`, `cap0046-scmap-keys-host-order` | diverged | pass |
| [js-stellar-sdk#1785](https://github.com/stellar/js-stellar-sdk/issues/1785): offer and muxed IDs | `cap0006-manage-buy-offer-id-above-2p53`, `cap0027-muxed-account-id-noncanonical-input` | diverged | pass |
| [js-stellar-sdk#1789](https://github.com/stellar/js-stellar-sdk/issues/1789): map entries dropped in native conversion | `cap0046-scmap-keys-collide-as-native` | diverged | pass |

Also run: [wallet-backend#753](https://github.com/stellar/wallet-backend/pull/753) (halt on a muxed Soroban source; mishandled, then pass) and [js-stellar-sdk#1823](https://github.com/stellar/js-stellar-sdk/issues/1823) (non-UTF-8 memo text; diverged on both versions, because upstream documented the behaviour and kept it).

- **wallet-backend** results come from replaying a ledger entry into the real `wallet-backend ingest` binary through a mock RPC `getLedgers` server, then comparing the database with the entry's manifest.
- **js-stellar-sdk** results come from running a value entry against the published npm releases.
- **Not covered:** the third producer of wallet-backend#716 (a muxed address in a SEP-41 event). Every section of [`repro/README.md`](repro/README.md) lists its own limits.

## Where the entries come from

| Source | Entries |
| --- | --- |
| Public testnet history | `cap0040-signed-payload-signer-added` (ledger 4437357) |
| stellar-core `--check-lcm` golden files | `cap0073-sac-trust-creates-trustline`, `cap0073-sac-trust-creates-trustline-signed-header` |
| A local stellar-core, generated by [`generator/muxed_soroban_source.mjs`](generator/muxed_soroban_source.mjs) | `cap0027-muxed-source-on-soroban-ttl-op` |
| Synthetic, flagged as such, built from the XDR-JSON recipes in [`generator/recipes/`](generator/recipes/) | the six value entries |

Every payload decodes and re-encodes byte for byte through [rs-stellar-xdr](https://github.com/stellar/rs-stellar-xdr) 30.0.0.

## Run it

Validate the corpus (schema, digests, round trip, expected values, recipes, index):

```
python3 -m venv .venv && .venv/bin/pip install jsonschema
cargo install --locked stellar-xdr --version 30.0.0 --features cli
.venv/bin/python tools/validate.py --check-index
```

Check the js-stellar-sdk verdicts recorded in the manifests (installs the SDK releases from npm):

```
python3 repro/check_js_sdk.py
```

Both run in CI on every push. The wallet-backend replays need Docker, PostgreSQL with TimescaleDB and four Go builds, so they are run by hand; the steps are in [`repro/README.md`](repro/README.md).

Nothing here needs network keys or funds, and running the checks needs no access to a Stellar network.

## Layout

```
schema/manifest.schema.json     manifest schema (JSON Schema 2020-12)
corpus/index.jsonl              generated; one line per entry
corpus/entries/<id>/            entry.json and the raw XDR payload
generator/                      recipes that produced the entries
tools/validate.py               corpus validator
repro/                          replay harness, SDK runner, evidence
docs/                           architecture, schema explanation, bug catalogue, design notes
```

## Status

A prototype, not a release. The schema is version 0.1 and may change. What the full project would add is described in the RFP and designed in [`docs/architecture.md`](docs/architecture.md): a larger corpus tagged per CAP, a generator, a Galexie-layout replay path, Go and Rust SDK runners, a linter and a hardening guide. Known gaps and open questions are in [`docs/design-notes.md`](docs/design-notes.md).
